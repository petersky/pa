# v0.2.29 — 0.2.29

**Release track:** release  
**Date:** 2026-07-28

## Summary

This release pins the UI to a locally vendored stable HTMX build and fixes PA MCP owner-channel resolution so agent tools reach the owning server when it is not bound to IPv4 loopback. Operators running Fleet offline or on LAN/Tailscale binds should upgrade.

## Highlights

- Vendor and serve HTMX 2.0.10 locally instead of loading HTMX 4 beta from a CDN
- Migrate UI event, history, and swap contracts to the HTMX 2 API
- Resolve the embedded PA MCP bridge from the owning server’s real bind address
- Gate ACP session readiness on an authenticated, instance-fenced owner API probe
- Expose sanitized MCP health in runtime and session responses

## Added

- Vendored `htmx.org@2.0.10` asset and license under `static/vendor/htmx/`
- HTMX delivery, security, update, and rollback policy documentation
- Process-local PA MCP owner-channel contract documentation
- Bounded MCP bridge retries/circuit breaking and sanitized health surfaces

## Changed

- Replace the runtime jsDelivr dependency on `htmx.org@4.0.0-beta5` with an exact locally served HTMX 2.0.10 build
- Align JavaScript event, history, error, request-header, and programmatic contracts with the HTMX 2 API
- Keep Fleet refresh cancellation PA-owned via `fetch()`/`AbortController`, then use `htmx.swap()` for successful fragment processing

## Fixed

- PA MCP owner channel no longer hard-codes `127.0.0.1`, so tools work when PA listens only on a concrete LAN or Tailscale address

## Upgrade

```bash
pa update
# or fresh install:
curl -fsSL https://raw.githubusercontent.com/petersky/pa/main/scripts/install-remote.sh | bash
```
