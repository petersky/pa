# v1.5.4 — Reliable starts and permission defaults

**Release track:** release

**Date:** 2026-10-15

## Summary

PA preserves project context and supported model settings when starting selected
work from a conversation. New Codex chats default to Full access; new card and
background workers default to Workspace Write with user/ACP approval review.
Explicit permission choices, model preferences, existing sessions, and PA's
separate auto-approve preference remain in effect.

## Highlights

- Multiple connected chats retain each current model's scoped native settings,
  including reasoning effort and Fast mode, regardless of advertisement order.
- Selected work inherits the primary card's project when the conversation has
  no project field, so repository work reaches normal isolated workspace admission.
- Routine pending admission and lost acknowledgements recover using the same
  saved request identity; genuine denials retain their reason.
- Issue-list tools accept public issue round trips and expose a writable projection
  while preserving started-work receipts and strict validation.

## Fixed

- Permission defaults follow the resulting agent's purpose across UI creation,
  standalone execution, linked attempts, and fleet/card dispatch.
- Workspace Write uses Codex's user/ACP reviewer so PA can answer native permission
  requests using its existing auto-approve setting. Intentionally selected Auto
  review continues to use Codex's native reviewer.
- Permission configuration readback agrees with provider state and the UI, and
  recovery preserves the existing session's mode.
- Chat header, artifact icons, and collapsible detail tabs include the already
  merged UI polish from PR464.

## Upgrade

Run `pa update` through the normal installation workflow. Agents restarting a
managed turn must use PA's durable restart handoff to preserve the exact session.
