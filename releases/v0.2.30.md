# v0.2.30 — 0.2.30

**Release track:** release  
**Date:** 2026-07-29

## Summary

This release hardens owner-channel readiness checks and build identity so remote dispatch works reliably across FastAPI versions and identical installs share the same build fingerprint.

## Highlights

- Owner readiness no longer crashes on newer FastAPI/Starlette route trees
- Owner-channel HTTP failures surface as `api_error` / `identity_missing` instead of false instance mismatches
- Asset/build fingerprints are content-based and stable across hosts
- Fresh remote dispatch sessions can pass readiness on FastAPI 0.140.x

## Fixed

- `/api/ready` inspects registered paths via FastAPI’s OpenAPI schema instead of assuming every route object has a `.path` attribute (avoids `AttributeError` on `_IncludedRouter` entries)
- Owner preflight classifies headerless API failures before treating a returned identity as mismatched
- Build IDs derive from deterministic file paths and contents, not installation mtimes

## Upgrade

```bash
pa update
# or fresh install:
curl -fsSL https://raw.githubusercontent.com/petersky/pa/main/scripts/install-remote.sh | bash
```
