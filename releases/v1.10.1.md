# v1.10.1 — 1.10.1

**Release track:** release  
**Date:** 2026-11-15

## Summary

Patch release focused on safer restart and workspace handling: read-only binding inspection, bounded tracked-prefix custody, startup block retention, and clearer restart evidence on the wire and through MCP. Operators dealing with restart handoffs, partial checkouts, or card-summary length failures should update.

## Highlights

- Inspect retained workspace bindings without restoring or delivering work
- Bounded tracked-prefix custody that archives changed HEAD files without rebuilding partial checkouts
- Automatic startup keeps binding and exhaustion blocks instead of clearing them
- Restart prompt wire evidence correlates with saved identity; fenced restart reconciliation is available over MCP
- Card summaries accept a length grace window and truncate excess instead of failing hard

## Added

- Read-only workspace binding inspection (`GET …/workspace-binding` and MCP `get_agent_session_workspace_binding`) for saved binding facts, audited history, and lease metadata
- Bounded tracked-prefix custody (`workspace_tracked_prefix_custody`) to prepare, attach, and verify archived changed HEAD prefixes from selected empty-index worktrees
- MCP exposure of fenced restart evidence reconciliation

## Changed

- Automatic startup retains binding and exhaustion blocks rather than dropping them
- Card summary sanitization allows a 200-character grace beyond the 600-character target and truncates longer text

## Fixed

- Restart prompt wire logs correlate `queued_prompt_id` and restart attempt with the saved identity without sending those fields to the provider
- Tracked prefixes are preserved through custody instead of rebuilding partial checkouts
- Over-long card summaries no longer reject solely for length within the grace window
