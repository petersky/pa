# v1.6.2

**Release track:** release  
**Date:** 2026-11-08

## Summary

Workspace cleanup now recognizes squash-merged pull requests. Previously, selected cleanup could refuse a lease whose PR was merged on GitHub, even when the caller supplied the PR number as proof. Anyone cleaning up retained worktrees should upgrade.

## Highlights

- Squash merges are proven by an exact three-way tree reproduction, not only per-file blob equality (#659).
- An explicit, freshly revalidated merged-PR proof is no longer masked by a stale watch for a different PR head (#659).

## Fixed

- **Squash merges with a concurrent edit to the same file.** If another change touched the same file between the branch's last sync and the squash, the PR head's blob differs from the squash result and the old check could never pass. Cleanup now also accepts the lease when a three-way merge of the PR head into the pre-merge target reproduces the squash commit's tree exactly. This is not weaker than the per-path check: any missing, extra or altered content changes the tree. It applies only to single-parent merge commits, runs in a throwaway object directory (no writes to the repository cache), and a conflict means "not proven".
- **Stale watch hiding the explicit proof.** A session with several merged PRs returned its newest merged watch even when it described a different head, and the explicit `merged_pr_number` proof was consulted only when no watch existed. Cleanup now prefers the watch whose head is the branch tip, and lets an explicit proof for the exact head supersede evidence about a different head.

## Unchanged

- A squash commit that adds a file the PR did not, or drops a change the PR made, is still rejected.
- Other cleanup guards (active owner, card acceptance, dirty or untracked files, expiry, pending restart) are untouched.

## Upgrade

```bash
pa update
# or fresh install:
curl -fsSL https://raw.githubusercontent.com/petersky/pa/main/scripts/install-remote.sh | bash
```
