# v1.0.6 — 1.0.6

**Release track:** release  
**Date:** 2026-08-15

## Summary

This release hardens startup readiness and clears event-loop stalls on hot request paths, so operators and agents get a reliable admission signal before traffic is admitted. It also adds Cursor Cloud agent environment guidance for contributors working in cloud VMs.

## Highlights

- `/api/ready` is now a cheap admission gate that waits for ACP and local sync repair before reporting ready
- `pa start` / `pa restart` probe `/api/ready` instead of liveness
- Hot-path responsiveness improvements: middleware off `BaseHTTPMiddleware`, bounded cards SQL, and cached fleet/telemetry/notification poll work
- OpenAPI schema warmed during kernel startup
- `AGENTS.md` documents Cursor Cloud setup, run, and test conventions

## Added

- Dedicated readiness admission path (`/api/ready`) with clearer startup gating
- `AGENTS.md` with Cursor Cloud development environment instructions

## Changed

- `pa start` and `pa restart` wait on readiness rather than liveness
- Remaining request middleware moved off Starlette `BaseHTTPMiddleware`
- Fleet, telemetry, and notification poll paths cache more aggressively so owner-channel probes stay fast
- Cards projection bounds SQL work before presentation joins

## Fixed

- Event-loop / hot-path stalls that could delay responsiveness under concurrent load
