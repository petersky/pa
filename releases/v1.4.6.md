# v1.4.6 — Recover authorized restart continuations

**Release track:** release

**Date:** 2026-09-12

## Summary

v1.4.6 repairs cold-start recovery of authorized restart continuations in human chats and records complete execution provenance before fresh dispatches start their provider.

## Highlights

- Resume an existing authorized restart continuation in its original human chat while holding unrelated automatic prompts.
- Remove the circular dependency between provider startup and the owner readiness probe.
- Preserve queue responsiveness and user-prompt priority while checking restart authorization.

## Fixed

- Provider owner probes check required API services, warmed routes and local sync repair without waiting on their own provider startup. Authentication and instance fencing remain enforced.
- Restart recovery validates the durable receipt against the exact session, prompt, principal, workspace, environment and execution binding before delivery. Operator pauses, cancellation and human takeover remain effective; unrelated automation is not authorized by the restart receipt.
- Receipt checks run off the event loop and revalidate current queue order and authority before starting a turn. Slow or failed checks do not block an eligible user prompt, and recovery recognizes a continuation already undergoing admission.
- Cold-restored sessions initialize execution selection auditing before admitting their queued continuation. Completed prompt evidence repairs receipt state without replaying the prompt.
- Genuinely fresh dispatches bind complete immutable execution provenance before provider admission. Existing bindings retain their original identity.
- Session status prioritizes the current in-flight turn and distinguishes operator pauses, human-control holds and provider recovery.
