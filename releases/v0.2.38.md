# v0.2.38 — 0.2.38

**Release track:** release  
**Date:** 2026-08-03

## Summary

This release hardens fleet MCP bootstrap and dispatch progress handling so fresh installs and long-running dispatches stay reliable, and documents the durable goal orchestration architecture for long-lived PA outcomes. Fleet operators and anyone who hit stdio MCP or progress-limit failures should update.

## Highlights

- Fix PA stdio MCP bootstrap preflight so fleet placement rejects broken MCP/provider setups before reservation
- Pin the packaged MCP SDK to `<2` to avoid FastMCP breakage on fresh installs
- Raise durable dispatch progress storage limits (2 KB validation commands, 64 KB progress envelopes)
- Recover gracefully from malformed historical progress side-channel records
- Document durable goal orchestration as an architecture blueprint

## Added

- Durable goal orchestration architecture proposal (`docs/DURABLE_GOAL_ORCHESTRATION.md`) linked from the main architecture doc (#192)
- `pa --version` support and clearer doctor diagnostics for MCP bootstrap failures (#193)

## Changed

- Increase sanitized validation-command storage to 2,000 characters and progress payload envelopes to 64,000 encoded bytes (#191)
- Keep compact UI command labels independently truncated and expandable (#191)
- Resolve the effective provider before placement and return structured recovery choices for unavailable provider/MCP bootstrap (#193)

## Fixed

- Packaged installs resolving incompatible `mcp` 2.x and failing PA stdio MCP bootstrap (#193)
- Fleet eligibility skipping a real stdio initialize/tools-list probe of the injected PA MCP child (#193)
- Nested TaskGroup errors discarding useful child stderr in `pa doctor` (#193)
- Malformed historical progress side-channel payloads disrupting healthy dispatch lifecycle records (#191, #193)

## Upgrade

```bash
pa update
# or fresh install:
curl -fsSL https://raw.githubusercontent.com/petersky/pa/main/scripts/install-remote.sh | bash
```
