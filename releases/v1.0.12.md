# v1.0.12 — 1.0.12

**Release track:** release  
**Date:** 2026-08-16

## Summary

This release makes local and fleet health harder to misread: `pa status` and `pa doctor` now report whether the process is actually serving and whether sync is consistent, and the server refreshes required fleet probes so stale overnight snapshots stop looking like live head mismatches. Operators debugging hung, loopback-bound, or out-of-sync instances should upgrade.

## Highlights

- `pa status` and `pa doctor` report serving, health, and sync consistency—not only OS service state
- Hung or loopback-bound processes no longer look healthy when only the service unit is checked
- Last-good fleet snapshots are treated as history; readiness comes from the latest probe attempt
- Server refreshes reachability, status, and sync probes after startup and on an interval
- Fleet overview refresh no longer runs inside pytest `TestClient` boots (avoids SQLite races in CI)

## Added

- Serving, health, and sync-consistency reporting in `pa status` and `pa doctor`

## Changed

- Fleet overview classifies readiness from the last probe attempt and refreshes required probes on the server instead of relying on the Fleet page alone
- CI pytest suite splits across four jobs; Actions runs on Node 24; `setup-uv` pinned to v10.0.1

## Fixed

- Timed-out sync probes no longer leave an overnight `consistent=false` payload treated as a live topology head mismatch
- Background fleet probe loop no longer races Kernel startup SQLite during test boots

## Upgrade

```bash
pa update
# or fresh install:
curl -fsSL https://raw.githubusercontent.com/petersky/pa/main/scripts/install-remote.sh | bash
```
