# v1.4.4 — Chat creation and safe dispatch recovery

**Release track:** release

**Date:** 2026-09-11

## Summary

v1.4.4 restores new-chat execution selection, keeps live conversation delivery responsive, and allows new dispatches after an expired lease belongs to a closed session.

## Fixed

- New chat automatically refreshes expired provider/model evidence. Cold providers can advertise models through a bounded, tool-free ACP discovery session using the configured executable and arguments.
- Explicit capability refresh can immediately retry failed discovery. Concurrent requests coalesce, repeated manual refreshes report their rate limit, and obsolete Start chat errors clear after recovery.
- Requested models, native settings, and hard constraints remain intact. Unverified capabilities stay unavailable, and rejection details explain how to recover.
- Timed-out or cancelled discovery reaps its provider process, including providers that ignore EOF and termination signals.
- Live chat replay and delayed mutation completion preserve prompt acknowledgement and recover durable results instead of leaving the user waiting for a manual refresh (#420).
- Closed sessions with expired worktree leases no longer permanently block successor admission; live, queued, recovering, and unpublished startup owners remain fenced (#422).
