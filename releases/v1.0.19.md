# v1.0.19 — 1.0.19

**Release track:** release  
**Date:** 2026-08-20

## Summary

This release improves agent chat reliability and ACP startup performance. It fixes duplicate chat turns caused by overly broad 409 error handling, prevents empty provider completions from being treated as success, and removes a multi-second event-loop block during OpenInterpreter preflight that could cause MCP startup failures.

## Highlights

- Prevent duplicate agent chat turns by preserving stable submission IDs across transient 409 responses
- Reject empty provider `end_turn` results and surface a recoverable failure instead of silent completion
- Replace OpenInterpreter full-binary regex scanning with bounded, cached catalog discovery off the event loop
- Persist phase-level ACP startup timestamps and durations for session admission diagnostics

## Added

- ACP startup phase tracing with persisted timestamps and durations from preference resolution through response readiness
- Typed recoverable failure when a provider ends a turn with no response, thought, tool, plan, or usage evidence
- Pending submission restoration after page refresh, with transcript/queue reconciliation and explicit same-ID retry
- Regression coverage for startup tracing, provider launch, bounded catalog discovery, and empty-turn handling

## Changed

- OpenInterpreter preflight uses bounded mmap/JSON catalog parsing with caching instead of scanning the full standalone binary on the request thread
- Agent chat sends the stable submission ID in both `client_prompt_id` and the HTTP `Idempotency-Key`, with server validation when both are present
- Submission IDs are cleared only on `client_prompt_id_conflict`; restart, reconnect, timeout, and recovery 409s retain the ID
- Composer suppresses repeated Send/Enter while acknowledgement is pending and shows Sending or Checking state
- Edits made during an in-flight request are treated as a new draft so they do not inherit the earlier submission ID

## Fixed

- Duplicate agent chat turns when non-idempotency 409 responses caused the client to discard its submission ID and retry with a new one
- ACP/MCP startup timeouts caused by a 12+ second synchronous OpenInterpreter binary scan blocking the event loop
- Empty MiniMax (and similar) provider turns accepted as successful completion despite no assistant output
