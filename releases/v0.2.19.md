# v0.2.19 — 0.2.19

**Release track:** release  
**Date:** 2026-07-25

## Summary

This release makes card dispatch a first-class fleet workflow—via CLI and MCP—while consolidating work onto the card/lane model, documenting API auth and remote dispatch, and hardening MCP/runtime error handling for operators and automation clients.

## Highlights

- Durable `pa card dispatch` CLI for admit/list/get/retry/cancel against fleet instances
- First-class MCP tools for card dispatch lifecycle (lookup, retry, cancel, preferred instance)
- Cards and lanes become the canonical work model, with legacy item/status compatibility retained
- OpenAPI docs for session/CSRF/bearer auth and the remote dispatch contract
- Clearer MCP validation errors, enum-backed mutation schemas, and list-filter serialization fixes

## Added

- Durable card dispatch CLI (`pa card dispatch`, plus list/get/retry/cancel) with project inference and provider/model/mode/effort/message/idempotency options
- Authenticated MCP fleet dispatch lifecycle tools (dispatch, lookup, retry, cancel, preferred-instance updates) routed through the durable local HTTP control plane
- OpenAPI security schemes and docs for PA session cookies, CSRF, user/instance bearer tokens, and remote-agent dispatch (target instance, card/project linkage, `Idempotency-Key`, conflicts, admission)

## Changed

- Consolidated item lifecycle onto cards/lanes as the canonical domain model, with compatibility DTOs, deprecation signaling, and legacy status-history replay into lanes
- MCP mutation/filter schemas now reuse HTTP domain enums for status, kind, lane, and related fields
- Recoverable server background failures (credential probes, heartbeats, workspace recovery) are handled as capability state instead of noisy supervisor loop failures
- Evidence-based warning thresholds for expected filesystem, SQLite, and Git provisioning latency

## Fixed

- Async repository inspection error persistence no longer raises `NameError` when persisting `GitInspectionError` after the `except` block
- MCP list tools omit blank filters and serialize enum filters correctly (including `kind` on `list_cards`)
- PA MCP HTTP failures preserve FastAPI/Pydantic validation details instead of collapsing into instance-mismatch messages
- Instance-mismatch reporting only when bridge and server identities actually diverge
