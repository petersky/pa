# v0.2.35 — 0.2.35

**Release track:** release  
**Date:** 2026-08-02

## Summary

This release hardens fleet remote dispatch so clients get a durable admission response sooner and targets are only used after realm projection convergence. Operators running multi-instance fleets should upgrade before relying on remote agent work under load or during sync catch-up.

## Highlights

- Remote dispatch returns a durable 202 admission before provisioning begins
- Idempotent remote starts are deduplicated before placement/provisioning can block replays
- Dispatch waits for target realm head and projection convergence, with recoverable retry signals
- Clearer dispatch lookup and target-not-ready errors (including Retry-After / retry_after_convergence)

## Changed

- Remote agent admission wakes provisioning shortly after the ASGI response path so admission is not blocked by workspace setup
- Dispatch lifecycle surfaces a distinct `provisioning` state (and allows cancel while provisioning)
- Target sync mismatch is reported as recoverable projection-not-ready (503) instead of a sync conflict when the peer has not converged
- Missing card/project lookups use structured error codes; target-side misses are marked recoverable after convergence

## Fixed

- Race where provisioning could consume the event loop before clients received durable dispatch admission
- Remote dispatch proceeding against targets whose durable head or projection had not caught up to the authority realm
