# v1.5.2 — 1.5.2

**Release track:** release  
**Date:** 2026-10-14

## Summary

Patch release for reliable card completion and browser automation. Local operators now receive a concrete sign-in path when a card requires human acceptance, failed status changes remain readable and restore the saved state, and Chromium keeps viewport settings across browser commands.

## Highlights

- Local operators can set a password with `pa user set-password local`, sign in, and accept a card after reviewing its current requirements.
- Authenticated human completion records one durable acceptance receipt while preserving criteria, evidence, and history.
- Failed card status changes display readable errors and restore the authoritative status instead of appearing to succeed.
- Browser resize settings persist across commands, navigation, media queries, and screenshots.

## Changed

- Password setup uses the running server's authenticated administration API. There is no assumed or default local password; password setup does not itself accept any card.
- Local mode without sign-in explains the supported operator flow when human acceptance is required.
- Stale or unverifiable card versions direct the operator to reload before retrying.

## Fixed

- Structured completion errors could display as an object string and leave a failed status selection visible.
- CLI, instance, MCP, or agent-session credentials mixed with browser cookies could be mistaken for a direct human card action.
- Chromium viewport emulation was lost when the DevTools connection closed after each command. The connection now persists for the attached page and closes on detach or failed startup; interrupted commands are not automatically replayed.

## Upgrade

```bash
pa update
# or fresh install:
curl -fsSL https://raw.githubusercontent.com/petersky/pa/main/scripts/install-remote.sh | bash
```

After installation, restart the running instance through the supported lifecycle flow. In an active PA-managed session, use the managed restart handoff. For cards requiring human acceptance, the actual operator sets a password if needed, signs in at `/login`, reviews the current criteria, and selects Done. Existing requirements and acceptance owners remain in force.
