# v1.10.3 — 1.10.3

**Release track:** release  
**Date:** 2026-11-22

## Summary

Patch release focused on reclaiming orphaned headless browsers and hardening restart, custody, and PR-supervision paths: killed owners no longer leave Chrome processes behind, inspection stays side-effect free, and supervision recovers through diagnostic failures. Operators running agent browsers, restart handoffs, or PR supervision should update.

## Highlights

- Reap orphaned headless browsers left by killed owners, with `PA_BROWSER_REGISTRY_DIR` inventoried in configuration
- Keep PR supervision alive through diagnostic failures and recover stopped controllers
- Inspect durable checkpoint custody and canonical restart evidence without recovery, audit, or receipt mutation
- Retain restart failure boundaries, fence explicit retries, and expose tracked custody guard refusal reasons
- Keep repository readiness inspectable after upstream deletion; wait for revision navigation before reading result metadata

## Added

- Configuration registry inventory for `PA_BROWSER_REGISTRY_DIR`
- Side-effect-free inspection of durable checkpoint custody and canonical restart evidence
- Exposed refusal reasons from the tracked custody guard

## Changed

- PR supervision continues through diagnostic failures and recovers stopped controllers
- Evidence cursors are bounded to the SQLite sequence range
- Revision navigation completes before result metadata is read
- Repository readiness remains inspectable after upstream deletion

## Fixed

- Orphaned headless browsers left by killed owners are reaped on the next launch
- Transcript initialization handles are closed and schema warning capture is isolated
- Restart failure boundaries are retained and explicit retries are fenced
