# v1.0.22 — 1.0.22

**Release track:** release  
**Date:** 2026-08-20

## Summary

This release hardens agent session startup and switching so chat routing, Codex MCP bootstrap, and fleet placement stay reliable under contention. Operators and anyone running agent chat or local dispatch should update.

## Highlights

- Bound and cancel session-owner lookups; fence recovery so stale failures cannot disable a newer session’s composer
- Speed up Codex session startup by proving MCP in the real provider context and reusing connected bootstrap evidence
- Treat card preferred capabilities as placement preferences so named local dispatch still works when ads are empty
- Raise the default local owner API budget to ten seconds to avoid false “unknown” outcomes under SQLite/write contention
- Skip repeated expensive MCP bootstrap children during forced dispatch when a fresh connected proof already exists

## Changed

- Default local owner API deadline is now ten seconds; longer durable-admission budgets remain available when set explicitly
- Card preferred capabilities are placement preferences; explicit execution and MCP capabilities stay hard requirements
- Codex MCP bootstrap observation ends as soon as startup succeeds and reuses live connected runtime/bootstrap proof

## Fixed

- Stale session-owner recovery/history/prompt callbacks could overwrite a newer session selection and disable its composer
- Codex startup could launch a duplicate PA stdio MCP child before the provider’s sandboxed server, adding ~8s without proving provider-context access
- Preferred card capabilities merged into hard dispatch requirements blocked named local dispatch when capability advertisements were empty
- Forced dispatch admission repeatedly spawned an expensive MCP bootstrap child even when fresh connected proof already existed
- Local MCP owner requests could report unknown outcomes under normal write contention because of a fixed two-second deadline
