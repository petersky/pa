# v1.6.3

**Release track:** release  
**Date:** 2026-11-08

## Summary

Two operator-facing fixes: the tool-activity and Terminal flyouts now open at the last entry, follow live output and load history lazily, and a recorded response to a session that was superseded by a linked run is no longer stuck on "Delivery failed" with a retry that can never work. Also includes two small performance changes merged from the linked systemic-latency run.

## Highlights

- Tool activity and Terminal open at the most recent entry, follow live output, and show only the latest entries (#663).
- A response recorded against a superseded session can be sent to its linked run or dismissed, and the card says why delivery failed (#665).
- Notification display labels are batched without hydrating linked records (#662); repository filesystem lock intervals are observable (#664).

## Fixed

- **Flyouts open at the top and never auto-scroll.** A hidden flyout had no scroll position, tool activity only followed when already near the bottom, and the terminal never followed at all. Both now open at the last entry, follow live output while you are at the bottom, leave you alone when you have scrolled up, and keep their position across history rebuilds.
- **Long history in the flyouts.** Only the 100 most recent tool-activity rows and 50 most recent terminal calls are rendered. Older tool rows are detached rather than destroyed (retention stays within the existing 300-row bound), and scrolling toward the top, or the new "Show earlier" controls, reveals the next page while keeping your place; once everything loaded is shown it asks for the next durable history page. Only a user gesture can trigger this, so restoring a scroll position can never cascade into loading the whole history.
- **Delivery to a superseded session retried forever.** A fenced source (superseded by an explicit linked attempt) can never accept the response, but was classed retryable. It is now non-retryable (`source_superseded`) with a recovery action.
- **The explicit repair refused fenced sources.** `transfer_continuation` rejected them as "not demonstrably unrecoverable". It now accepts a source only when the link is exact and mutual: a `linked` fence on the source naming this successor and the source dispatch, and the matching origin on the successor.
- **The card hid the cause and offered no way out.** It now shows the stored failure reason, offers "Send the recorded response to the linked run" (transfer, then retry, once) and "Dismiss without delivering" (which preserves the saved response). The offer is derived from the fence, so records stored before this release get it without a migration.
- **Interrupted deliveries.** A delivery cancelled mid-flight is no longer left in "delivery pending"; it ends as a retryable `interrupted` failure.

## Changed

- Notification display labels are batched without hydrating linked records (#662).
- Repository filesystem lock intervals are observed for performance diagnosis (#664).

## Known issues

- A notification that already shows "Delivery failed" keeps its stored state until you act on it; use the new "Send the recorded response to the linked run" or "Dismiss without delivering" controls.
