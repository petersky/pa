# v1.6.0 — 1.6.0

**Release track:** release  
**Date:** 2026-11-07

## Summary

v1.6.0 is a chat, operations, and runtime hardening release. Operators and chat users get clearer fork/recovery UX, sandboxed visualizations, tighter Work and agent-settings controls, better backup observability, and a large set of performance and reliability fixes under the hood.

## Highlights

- Chat forks show source attribution and inherited context boundaries, and keep that metadata through recovery
- Persistent sandboxed visualizations render in chat
- Work discovery stays compact with visible active filters; agent settings make scope and inherited defaults explicit
- Manual backups return durable receipts; backup capture documents historical limitations
- Broad latency and retention work: less wire amplification, fewer retained copies, offloaded authority reads, and safer continuation/restart handling

## Added

- Chat fork source and inherited context boundary display
- Persistent sandboxed visualizations in PA chat
- Design-first UX guidance with verified core journeys
- Compact Work discovery controls with exposed active filters
- Explicit agent settings scope and inherited defaults
- Bounded owner diagnostics and withdrawal of unanswered operator requests
- Durable receipts for long-running manual backups, plus backup run lookup / optional preservation MCP contracts
- Backup capture that preserves available data with explicit historical limitations

## Changed

- Reduced session-list JSON wire amplification without dropping values
- Consolidated chat recovery into a single notice path with current issue counts
- Separated current Operations health from historical diagnostics and preserved graph focus when disclosing details
- Scheduled the user-facing PA service as interactive work
- Preserved system Git configuration during workspace provisioning
- Extensive runtime/performance improvements: offloaded collaboration/browser/Fleet/session authority reads, batched retention and GC, fewer retained dispatch/progress copies, bounded gzip Fleet responses, and lighter OpenAPI/startup/schema work

## Fixed

- ACP selects the saved model before Codex session restoration
- Fork attribution preserved after session recovery; unrecognized provenance metadata is tolerated
- Doctor distinguishes advertised health failures from local timeouts
- Pending restart continuations protected from completion cleanup; authenticated dispatch continuations kept out of web intake
- Closed sessions restored through admitted dispatch retries
- Workspace base provenance preserved during recovery and response delivery
- Backup scheduling stays alive after a limited recovery point
- Incoming sync publication fixed; derived database work closed cleanly
- Verifier readiness honors terminal follow-up status codes; malformed dual-status representations stay pending
