# v1.0.3 — 1.0.3

**Release track:** release  
**Date:** 2026-08-13

## Summary

This release hardens PA MCP bootstrap and Codex sandbox admission so MCP tools stay unique, probes stay bounded, and Codex sessions can reach the PA owner socket without widening sandbox access. Operators using Codex or anyone hitting MCP bootstrap or tool-registration failures should update.

## Highlights

- Codex PA MCP owner sandbox access so workspace-write and read-only Codex sessions can start PA MCP
- MCP bootstrap is unique and bounded: duplicate tool names fail closed; probe refreshes coalesce and stay cache-bounded
- Codex sandbox grants only the per-instance owner socket directory, not `PA_DATA_DIR`

## Changed

- MCP tool registration is unique: each tool name is reserved once, and duplicate or reload registration fails closed
- MCP bootstrap probes are bounded: forced refreshes coalesce, warm cache stays within SLO, cancelled waiters can retry, and failed handshakes cache as unavailable

## Fixed

- Codex PA MCP owner sandbox access: Codex stdio MCP can reach the private PA owner socket without cancelling startup

## Upgrade

```bash
pa update
# or fresh install:
curl -fsSL https://raw.githubusercontent.com/petersky/pa/main/scripts/install-remote.sh | bash
```
