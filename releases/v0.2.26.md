**Release track:** release

## Summary

This release makes fleet dispatch capacity an explicit, configurable limit: operators can set global and per-provider ceilings, see workload-aware utilization, and rely on durable admission reservations with clear rejection details when an instance is full.

## Highlights

- Typed global and provider-specific dispatch capacity across config, API, MCP, CLI, Settings, and Fleet Overview
- Workload-aware utilization based on prompting turns, queued prompts, and durable starting reservations
- Durable, atomic admission reservations with idempotent retry and timeout/release handling
- Administrator capacity override with audited reason
- Compatibility path for legacy `capacity:N` tags and a documented default of 4

## Added

- `dispatch_capacity` and optional provider ceilings (Settings → Instance, `pa config set`, `PATCH /api/config/capacity`, MCP `set_dispatch_capacity`)
- Fleet Overview and card dispatch UI surfacing of capacity, utilization, and rejection detail
- Durable authority-side dispatch reservations and audited `capacity_override` with reason
- `docs/FLEET_CAPACITY.md` describing the capacity contract

## Changed

- Placement and named dispatch share one fresh activity/capacity model; effective capacity reports its source (`configured`, `legacy_capability`, or `documented_default`)
- Legacy `capacity:N` capability tags remain as a mixed-version fallback behind the typed setting
