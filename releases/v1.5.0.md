# v1.5.0 — Faster pages and automated SQLite maintenance

**Release track:** release  
**Date:** 2026-09-13

## Summary

v1.5.0 cuts Home, Agent, and Fleet page latency and adds automatic SQLite maintenance so larger instances stay responsive without manual compaction.

## Highlights

- Home, Agent, and Fleet routes do less work per request (SQL-backed home counts, bounded fleet activity summaries, filtered session queries, background catalog warm)
- Automatic SQLite maintenance on startup and every 24 hours by default (integrity checks, planner stats, WAL checkpoints, and VACUUM when free pages can be reclaimed)
- `pa maintain status` reports the last sweep; `pa maintain run` triggers the same sweep manually
- Sync backs off failed peers and keeps object catalog totals transactionally instead of scanning on every read
- CardProjection reuses one SQLite connection per thread and restores more safely around WAL checkpoints

## Added

- Background maintenance worker that maintains both `pa.db` and `pa.transcripts.db` after retention cleanup, with disk-space checks, busy-database deferral, and shutdown interruption
- Richer `pa maintain status` output (per-database allocated/free bytes before and after compaction, deferral reasons)
- Benchmark helper for disposable Home/Agent latency samples against a retained-data fixture

## Changed

- Fleet activity carries bounded dispatch summaries; full materialization plans and historical evidence stay on dispatch detail endpoints, and cache writes persist only changed dimensions
- Home uses SQL lane counts and body-free, batched lifecycle evidence instead of building fleet topology or walking every card
- Completion reconciliation filters pending, blocked, or prompted work before limiting or copying records; periodic sync backs off failed peers while healthy peers continue
- Session list and Agent page queries filter purpose/archive state in SQLite; snapshot/history assembly runs off the event loop, and history fetch can overlap route resolution for a known owner
- Codex startup consumes already-reported MCP failures without a fixed two-second wait
- Offline `pa maintain compact` remains available under the exclusive data-directory writer lock (stop PA before using it)
