# v1.4.8 — Stop retrying resolved notification responses

**Release track:** release

**Date:** 2026-09-12

## Summary

v1.4.8 closes response delivery when a notification request is resolved. Retired requests preserve their saved response and historical delivery outcome without inviting another reply or retry.

## Fixed

- Resolved notification requests reject new response-delivery attempts with `interaction_already_resolved`. Replaying an existing response idempotency key remains read-only and preserves the recorded outcome.
- Notification details hide response and retry controls for resolved requests, including stale failed or pending interactions. Status text distinguishes historical delivery failures and closure without confirmed delivery from an active request awaiting action.
- Resolved remote copies no longer instruct users to respond on the owning instance. Existing response history and continuation links remain available.
